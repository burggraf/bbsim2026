Selection: `game_start_info.season=2019 AND is_regular_season=TRUE AND home_league/away_league IN ('AL','NL')`. Schedule uses 2019 date and both leagues AL/NL; **not joined one-to-one** because it lacks `game_id`, and postponements/makeups/doubleheaders need explicit reconciliation. `source_type='PlayByPlay'` is PBP; `BoxScore` or `Event` is box/event source, not necessarily a played-game count. `game_results` presence is a played-result proxy, not independent proof. PBP event rows include `no_play_flag` and are distinguished from real PA and non-PA rows.

## Counts and missingness

Report each fraction as `count / denominator`, unknown as `unknown / denominator`. `count` is a subset except where explicitly labeled a sum or distinct-ID count in the SQL note; count plus unknown need not equal the denominator for incidence metrics. Do not interpret a zero credit as a missing measurement. The source tables' derived/aggregated flags are **not** direct observations of all eligible opportunities. The 69-metric result below is from the final SQL, not the earlier exploratory 58-metric query. For metrics counting distinct IDs (e.g. `teams_distinct`) or credits (e.g. `fielding_errors`), the first fraction is **not** a completeness percentage; see each metric's precise definition in `audits/2019.sql`.

## Observed, inferred and unavailable

- **Recorded/source-reported:** game start/date/team/park/source type; lineup-map IDs; event PA/result, runner movements, fielding credits where source detail exists. Source records are not guaranteed error-free.
- **Derived/inferred:** [`event_states_full`](https://github.com/droher/baseball.computer/blob/b449f7bec49f852c27803e096303a4c78ac661b9/bc/models/intermediate/states/event_states_full.sql) before/after base-out/score; [`event_states_batter_pitcher`](https://github.com/droher/baseball.computer/blob/b449f7bec49f852c27803e096303a4c78ac661b9/bc/models/intermediate/states/event_states_batter_pitcher.sql) effective hands (explicit event hand if supplied, else bio/opponent hand, including switch-hitter inference); [`calc_batted_ball_type`](https://github.com/droher/baseball.computer/blob/b449f7bec49f852c27803e096303a4c78ac661b9/bc/models/intermediate/event_level/calc_batted_ball_type.sql) contact trajectory/location (explicit trajectory-deduced flag, location can also be fielder-inferred); [`event_baserunning_stats`](https://github.com/droher/baseball.computer/blob/b449f7bec49f852c27803e096303a4c78ac661b9/bc/models/intermediate/event_level/event_baserunning_stats.sql) opportunity flags; source-computed fielding statistics. Completeness must be checked against actual eligible records rather than assumed from column existence.
- **Not established here:** independent schedule-to-game matching, full pitcher responsibility/runner advances at every boundary (despite source after-runner slots in `event_base_out_states`), actual range/arm or play opportunity quality, date-accurate active roster/transactions, complete era-rule exceptions, reproducible season-filtered byte transfer and offline viability. `use_dh`, date, game type and league are inputs, not a complete 2019 rules engine. ## Verification and limitations

First complete run (2026-10-10 UTC): `duckdb :memory: -csv -noheader < audits/2019.sql > /tmp/bbsim-f01-2019.csv` exited 0 (135 seconds); `python3 audits/verify_2019.py /tmp/bbsim-f01-2019.csv` printed `validated 69 metrics; 2429 games; 222047 events`; aggregate CSV SHA-256 `775e9629132013f1e448e1f5d62636a7da14bccb007315cb66568a3a8ee210f3`. `python3 -m unittest discover -s tests -v` passed 7/7; `git diff --check` passed. A second independent run of the same SQL exited 0 (58 seconds), again validated 69 metrics and produced the **byte-identical** aggregate CSV (`cmp /tmp/bbsim-f01-2019-first.csv /tmp/bbsim-f01-2019-second.csv` exited 0; SHA-256 again `775e9629132013f1e448e1f5d62636a7da14bccb007315cb66568a3a8ee210f3`). A fresh public catalog GET after both runs matched the initial metadata byte-for-byte (SHA-256 above). A one-off check parsed this report's full table against the CSV and confirmed all 69 count/denominator/unknown triplets and rounded rates. Fresh `python3 -m unittest discover -s tests -v` passed 7/7 and `git diff --check` exited 0. No source rows were written to Git or the report. Exploratory failures retained: `duckdb` rejected reserved alias `unknown` (parser), an unbalanced occupied-runner expression (parser), then `len(MAP)` (binder). The next aggregation yielded `fielding_slots: (43722, 46150, -2428)` and the validator correctly failed; source maps hold 10 slots per side in 1,214 DH games and nine in 1,215 non-DH games. Denominators are now DH-aware. A further run hit a parser error (`er-event rows`) because the SQL file was edited while DuckDB was streaming stdin; the query is rerun only after edits finish. These are **failures**, not audit passes. Raw failure signatures:
